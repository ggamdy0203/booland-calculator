# 부동산 뉴스 통합 수집기 — 설계 문서

날짜: 2026-06-22

## 목적

네이버, 다음, 매일경제, 한국경제, 부동산114, 직방, 호갱노노 등 여러 사이트의 부동산 관련 뉴스/기사를 자동으로 모아서 한 웹페이지에서 한눈에 볼 수 있게 한다. 알림(이메일/카카오톡)은 이번 범위에서 제외하고, 이후 별도 작업으로 추가한다.

## 요구사항 요약

- **대상 사이트**: 한국경제, 매일경제, 네이버 부동산뉴스, 다음 부동산뉴스, 부동산114, 직방, 호갱노노
- **필터링**: 없음 — 전수 수집해서 모두 보여줌 (이후 태그/사이트별 필터 전환은 화면에서 지원)
- **수집 주기**: 3~4시간 간격
- **알림**: 이번 범위 제외 (추후 작업)
- **화면 구성**: 통합 타임라인 기본, 사이트별 칩 클릭으로 필터 전환 가능
- **저장 위치**: 새 GitHub 레포지토리 (예: `real-estate-news`)

## 아키텍처

서버 없이 동작하는 정적 구조를 택한다 (`rental.html`과 동일한 패턴).

- **수집**: Python 스크립트, 사이트별 RSS 파싱(가능한 경우) 또는 HTML 스크래핑
- **실행**: GitHub Actions 크론(3~4시간 간격)이 스크립트를 실행하고 결과를 `data/news.json`으로 커밋
- **화면**: GitHub Pages가 정적 HTML/JS로 `data/news.json`을 fetch해서 렌더링 (서버 불필요, 같은 도메인이므로 CORS 문제 없음)

### 폴더 구조

```
real-estate-news/
├── .github/workflows/collect.yml   # 3~4시간마다 실행되는 GitHub Actions
├── scraper/
│   ├── main.py                     # 전체 수집 실행 (사이트별 모듈 호출 + 병합 + 중복제거 + 저장)
│   ├── sources/
│   │   ├── hankyung.py             # 한국경제 (RSS)
│   │   ├── mk.py                   # 매일경제 (RSS)
│   │   ├── naver.py                # 네이버 부동산뉴스 (스크래핑)
│   │   ├── daum.py                 # 다음 부동산뉴스 (스크래핑)
│   │   ├── budongsan114.py         # 부동산114 (스크래핑)
│   │   ├── zigbang.py              # 직방 (스크래핑)
│   │   └── hogangnono.py           # 호갱노노 (스크래핑)
│   └── dedupe.py                   # 중복 기사 제거
├── data/
│   └── news.json                   # 수집 결과 (최근 14일치 누적)
└── index.html                      # GitHub Pages로 보여주는 화면
```

각 `sources/*.py`는 동일한 인터페이스(`fetch() -> List[NewsItem]`)를 갖는다. 사이트가 추가/삭제되어도 `main.py`는 변경할 필요가 없다.

## 데이터 구조

```json
// data/news.json
{
  "updatedAt": "2026-06-22T09:00:00+09:00",
  "items": [
    {
      "id": "naver-2026062209-ab12cd",
      "source": "네이버",
      "title": "기사 제목",
      "url": "https://...",
      "publishedAt": "2026-06-22T08:30:00+09:00",
      "summary": "기사 요약 1~2줄 (있으면, 없으면 빈 문자열)"
    }
  ]
}
```

`source` 값은 다음 중 하나: `한국경제`, `매일경제`, `네이버`, `다음`, `부동산114`, `직방`, `호갱노노`.

## 중복 제거

같은 기사가 여러 포털에 동시 게재되는 경우가 흔하다. 제목을 정규화(공백/특수문자 제거, 소문자화)한 뒤 완전히 일치하는 경우만 중복으로 판단해 제거한다. 유사도 기반 매칭은 하지 않는다(오탐 위험 + YAGNI).

## 보관 기간

`data/news.json`은 최근 14일치만 유지한다. `main.py`가 수집 결과를 병합할 때 14일보다 오래된 항목은 제거한다.

## 프런트엔드 (index.html)

- 순수 HTML/CSS/Vanilla JS, 빌드 과정 없음 (`rental.html`과 동일한 패턴)
- 상단에 사이트별 토글 칩(전체 / 한국경제 / 매일경제 / 네이버 / 다음 / 부동산114 / 직방 / 호갱노노)
- 기본 화면: 모든 사이트의 기사를 발행시각 기준 통합 타임라인으로 표시
- 칩 클릭 시 해당 사이트 기사만 필터링하여 표시
- 기사 제목 클릭 시 원문을 새 탭에서 열기
- `data/news.json`을 `fetch`로 불러와 렌더링 (같은 GitHub Pages 도메인이므로 CORS 문제 없음)

## 에러 처리

- 사이트별 수집 함수는 `main.py`에서 개별적으로 try/except로 감싸서 실행한다. 한 사이트의 수집이 실패(사이트 구조 변경, 타임아웃 등)해도 나머지 사이트 수집과 전체 워크플로우는 계속 진행된다.
- 실패한 사이트는 GitHub Actions 워크플로우 로그에 사이트명과 에러 메시지를 남긴다. 별도 알림 발송은 하지 않는다(이번 범위 제외).

## 범위 제외 (이후 작업)

- 이메일/카카오톡 알림
- 키워드 기반 필터링
- 유사 기사 묶기(클러스터링)
